## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Some Google Calendar events visible in the LifeOS week view disappear after refreshing the page, even though the selected week and account remain unchanged. Ensure event loading and rendering are stable across browser refreshes so the same visible date range produces the same event set.
<!-- SECTION:DESCRIPTION:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
## Plan
1. Prevent obsolete calendar event requests from overwriting newer date-range results by tracking the latest request in `useCalendarEvents`.
2. Gate event loading on confirmed Google OAuth connection state so refresh does not issue requests while disconnected or while connection status is unresolved.
3. Add focused hook coverage for out-of-order responses and disabled loading if the existing frontend test setup supports it.
4. Run frontend build and focused lint checks plus backend tests, then record verification evidence.

Verification exposed that Vitest did not resolve the application's existing `@/` import alias even though production builds did. Add the explicit Vite alias required to execute the focused regression test; this is test/configuration support for the same bug fix, not a product behavior change.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Root cause confirmed: on hard refresh, `usePersistentState` first renders default month/current-date values and hydrates the saved week afterward. This launched overlapping month and week event requests; whichever resolved last overwrote state. For the Aug 30–Sep 5 example, the stale month query started Sep 1 and therefore removed exactly Sunday and Monday events from the hydrated week view. Added latest-request protection and OAuth-status gating in `useCalendarEvents`, plus a deterministic regression test that resolves the obsolete request last. Added isolated Vitest config for jsdom and project alias resolution. Verification passed: focused Biome check, 2 Vitest regression tests, frontend production build, backend `go test ./...`, and `git diff --check`.
<!-- SECTION:NOTES:END -->
