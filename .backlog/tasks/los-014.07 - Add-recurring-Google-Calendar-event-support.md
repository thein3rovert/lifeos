## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Support recurring calendar events in LifeOS so users can create repeating schedules for selected weekdays and can recognize existing Google Calendar recurrence instances. Recurrence behavior must remain compatible with Google Calendar and distinguish a single occurrence from its series.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Event creation supports a non-recurring option and weekly recurrence on one or more selected weekdays
- [ ] #2 Recurring event creation supports an end choice of never or a selected date
- [x] #3 Existing recurring Google Calendar instances are identified in API responses and display a clear recurring indicator in month and week views
- [ ] #4 The event form identifies when an opened event belongs to a recurring series
- [ ] #5 Editing or deleting a recurring event requires an explicit choice between the selected occurrence and the entire series
- [ ] #6 Dragging or resizing a recurring event requires an explicit occurrence-versus-series choice before persistence
- [x] #7 Existing non-recurring event create edit delete drag resize and duplicate behavior remains functional
- [x] #8 Backend tests and focused frontend tests build and lint checks pass
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
## Implementation plan
1. Extend calendar API models with validated weekly recurrence input and normalized recurrence metadata for expanded Google instances.
2. Build weekly RRULEs server-side using selected weekdays, browser IANA timezone, and optional inclusive-until date; paginate event listing and enrich recurring instances from their master event.
3. Add recurrence controls to event creation and recurring indicators to month/week event rendering.
4. Add a reusable occurrence-versus-series chooser for edit, delete, drag, and resize. Occurrence operations target the instance ID; series operations target the returned master ID and refresh Google-expanded instances.
5. Preserve existing one-off behavior and add backend/frontend recurrence tests plus build/lint verification.

For safety, series drag/resize will only apply changes Google can represent consistently; cross-weekday series moves will shift the weekly BYDAY pattern with the move rather than leaving a contradictory recurrence rule.

### Recurrence editor correction
- The first implementation exposed recurrence controls only in create mode and used browser prompt text for mutation scope, so existing recurring rules could not actually be edited from the form and the scope UX was inadequate.
- Parse the enriched weekly RRULE into editable weekday/end controls for recurring events, allow recurrence updates on the series master, and replace browser prompts with an explicit in-app occurrence/series/cancel dialog.
- Ensure new-event recurrence controls are visible and testable in the rendered form, then rerun live-focused frontend/backend verification before marking the criteria complete again.
<!-- SECTION:PLAN:END -->
