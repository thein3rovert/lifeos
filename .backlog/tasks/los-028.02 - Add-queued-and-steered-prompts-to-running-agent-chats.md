## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Allow users to add context while an OpenCode V2 agent response is running by choosing whether a follow-up prompt should steer the active turn or queue for delivery afterward.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Composer remains available while an agent response is running
- [x] #2 Users can choose steer or queue delivery for a follow-up prompt
- [x] #3 Queued and steered messages show their delivery state in the transcript
- [x] #4 Delivery failures can be retried without losing text or context attachments
- [x] #5 Tests cover both delivery modes and ordering
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. Extend send payloads with a V2 delivery mode (steer or queue) and preserve context-reference resolution. 2. Use OpenCode V2 session.prompt delivery semantics while a session is busy, with stable message IDs and persisted LifeOS delivery state. 3. Keep the composer enabled during execution, add a compact delivery-mode selector, and show queued/steered/pending/failed state in transcript. 4. Add retry behavior and tests for ordering, state persistence, attachments, and regressions.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Implemented OpenCode V2 steer/queue delivery through every layer with persisted LifeOS delivery metadata, simultaneous request ordering, session-aware stop, assistant deduplication, and retry preserving text/context/mode. Verification: 18 sidecar tests, all Go tests, and 18 focused web tests passed.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Added queued and steered follow-up prompts while agent work is running. The composer remains available, delivery mode flows through OpenCode V2, transcript states persist across refresh, and failed deliveries can be retried with original content and Smart Board attachments. Multiple concurrent waits retain order and session-level stop behavior.
