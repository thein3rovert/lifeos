## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Build the new `/calendar` route + calendar UI on the frontend (TanStack Start). Includes the Google connect/disconnect flow.

**Route:**
- `web/src/routes/calendar/index.tsx` — new file-based route rendering a `CalendarPage` component.
- Add a nav link in `web/src/components/layout/Sidebar.tsx` under `mainNav` (alongside `/agent`, `/skills`, `/notes`, `/settings`).

**Components to build (suggested structure under `web/src/features/calendar/components/`):**
- `CalendarPage.tsx` — top-level: view toggle (month/week), navigation buttons (prev/next/today), Google connect/disconnect button, renders the active view.
- `MonthView.tsx` — 7-column day grid; fetches events for the visible month; renders event chips on each day. Habit checkboxes should render on each day cell (handled in LOS-014.05).
- `WeekView.tsx` — 7 columns × time-of-day rows; events positioned at correct time slots; clicking empty time opens a create-event form.
- `EventForm.tsx` — modal/inline form for create/edit/delete events (title, start, end, description, location). Uses the backend endpoints from LOS-014.02.

**Google connect flow:**
- A "Connect Google Calendar" button when no token is connected. Clicking redirects to `GET /api/calendar/oauth/start`.
- After the OAuth callback redirects back to `/calendar`, the page fetches events.
- "Disconnect" button hits the disconnect endpoint and re-renders an empty calendar with the connect prompt.

**API client:**
- `web/src/lib/api/calendar.ts` — new: `getEvents(start, end)`, `createEvent(body)`, `updateEvent(id, body)`, `deleteEvent(id)`, `getOAuthStartUrl()`, `disconnect()`. Re-export from `lib/api.ts` barrel.
- `web/src/hooks/useCalendarEvents.ts` — fetch hook mirroring `useSmartBoardPanel` pattern: takes a date range, fetches events, refetches on month/week navigation.

**Styling:** Follow the Atlas design system (doc/atlas-design-guide.md). Use real token-backed classes — `bg-raised`, `bg-base`, `border-default`, `text-primary`, `text-secondary`. Reuse existing UI primitives where possible (Button, Dialog, Input, Badge, Toast). **Do NOT use no-op tokens like `bg-tertiary`/`bg-secondary`** — LOS-009 established that convention.

**Depends on:** LOS-014.02 (backend sync) for the API endpoints.

## LOS-014.04 — Calendar frontend

### Research findings
- **Route:** file-based, no loader needed. Mirror `/agent` route: `createFileRoute('/calendar/')({ component: CalendarPage })`. Route tree auto-generates on build.
- **Sidebar:** `mainNav` array in `Sidebar.tsx:21-26`. Add `{ to: '/calendar', label: 'Calendar', icon: Calendar }` (import `Calendar` from lucide-react).
- **API client:** mirror `smartboardApi` pattern. New file `web/src/lib/api/calendar.ts`. Add to barrel `lib/api/index.ts`. Key correction: `getOAuthStartUrl()` is NOT a fetch — `GET /api/calendar/oauth/start` returns a 307 redirect. Make it a URL builder: `() => apiUrl('/api/calendar/oauth/start')`. Frontend uses `window.location.href = ...` to trigger the redirect.
- **Hook:** bespoke pattern (mirror `useSmartBoardPanel`): `useCalendarEvents(start, end)` with `events`, `loading`, `error`, `refresh`. Refetch on range change via `useEffect`.
- **UI primitives available:** Button (variants: primary/secondary/ghost/danger/neuro), Dialog (composable: Dialog/DialogHeader/DialogBody/DialogFooter), Input, Badge, Toast, Select, EmptyState, ErrorComponent, Skeleton.
- **No date library.** Hand-roll calendar grid with native `Date`. Need a small `utils.ts` for: `startOfWeek`, `startOfMonth`, `buildMonthGrid`, `formatTime`, `isSameDay`.
- **Atlas tokens confirmed:** `bg-base`, `bg-raised`, `bg-input`, `bg-tab-active`, `bg-hover`, `bg-active`, `bg-selected`, `text-primary`, `text-secondary`, `text-tertiary`, `border-default`, `bg-highlight`, `text-highlight`, status colors.
- **Controlled form pattern:** parent owns form state (title, start, end, description), Dialog renders the form, save calls API. Mirror LOS-010's controlled `InlineCanvasEditor` approach.
- **`usePersistentState`** available from LOS-010 — use it to persist the selected view (month/week) + current date across navigation.

**Phase 2 done + committed (bbea915).** Calendar route + page shell working.

**What works:**
- /calendar route exists, clickable in sidebar
- Month/Week view toggle (persisted across nav via usePersistentState)
- Prev/Next/Today navigation
- Google Connect button → OAuth flow → tokens saved → status updates → calendar body renders
- Google Disconnect button → clears tokens → empty state with connect prompt
- Placeholder grids for month + week (events render in Phase 3)

**Known issue with OAuth callback redirect:**
Google rejects raw IP addresses (like Tailscale 100.x.x.x) as redirect URIs — only localhost is allowed for IP-based dev. So GOOGLE_REDIRECT_URI stays as `http://localhost:6060/api/calendar/oauth/callback`.

What happens in practice: after consent, Google redirects the browser to `localhost:6060/callback` → backend saves tokens → backend redirects browser to `FRONTEND_URL/calendar`. If FRONTEND_URL is a Tailscale URL, this works. But the user sees `localhost` in the URL bar during the callback step and has to manually swap it to their Tailscale URL to get back to the app.

**Workaround for now:** user manually types their Tailscale URL after the consent screen. Tokens are already saved by then so the calendar works once they land on /calendar.

**Future fix (out of scope for 014.04):** set up a Tailscale MagicDNS hostname (e.g. lifeos.ts.net) so Google accepts it as a redirect URI. Then the flow is seamless.

**Also done in this commit:** split .env into .env (prod) and .env.dev (native dev) so dev and prod don't share env vars. Updated vite.config.ts, scripts/dev.sh, and .envrc to load .env.dev first.

**Rewrote calendar UI from scratch (custom implementation).**

Tried FullCalendar first — broke SSR with `Class constructor DayTableView cannot be invoked without 'new'`. Tried Schedule-X next — rendered fine, but drag-to-create and drag-and-drop are behind paid plugins. User decided to hand-roll a minimal calendar instead.

**What's built:**
- `MonthView.tsx` — 7-column grid with day headers, event chips per day (max 3 visible + '+N more'), today ring highlight, dimmer non-current-month days.
- `WeekView.tsx` — 7 day columns × hourly rows (6 AM – 11 PM, 48px per hour), events absolutely-positioned by start/end time, today column tinted with `bg-selected`.
- Both use Atlas tokens exclusively: `bg-raised`, `bg-base`, `bg-selected`, `bg-highlight/25`, `border-default`, `border-subtle`, `text-primary/secondary/tertiary`.
- Click day/slot fires `onDayClick`/`onSlotClick` (Phase 4 wires to create dialog).
- Click event chip fires `onEventClick` (Phase 4 wires to edit dialog).

**Pros of custom over library:**
- Zero deps, no SSR issues, no paid tiers.
- Full Atlas theming from day one.
- ~250 lines total — easy to modify.

**Trade-offs (user accepted):**
- No drag-to-move/resize events (would need custom pointer event handling — out of scope for now).
- Interaction limited to clicks (which is enough for MVP).

**Next (Phase 4):**
- Build EventForm dialog for create/edit/delete.
- Wire `onDayClick`/`onSlotClick`/`onEventClick` to open the dialog.
- POST/PATCH/DELETE via `api.calendar.*` (backend is done).

Still uses `usePersistentState` for view/date, still supports Google connect/disconnect + auto-fetch on connect.
