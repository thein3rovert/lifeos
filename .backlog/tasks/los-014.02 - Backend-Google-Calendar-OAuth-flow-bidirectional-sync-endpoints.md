## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement the Go backend that handles Google OAuth and the bidirectional Calendar sync.

Part 1 — **OAuth flow:**
- `GET /api/calendar/oauth/start` → redirects to Google consent URL with `calendar.events` scope
- `GET /api/calendar/oauth/callback` → exchanges code for tokens, persists them, redirects to frontend
- Token storage: new `google_oauth_tokens` table (or a JSON column on a settings table). Store access + refresh tokens + expiry.
- Token refresh: a helper that checks expiry and refreshes via the refresh token before each API call.

Part 2 — **Calendar API endpoints:**
- `GET /api/calendar/events?start=<RFC3339>&end=<RFC3339>` → fetch events from the user's primary Google Calendar. Return a normalized JSON shape `{ id, title, start, end, description?, location? }`.
- `POST /api/calendar/events` → create event in Google Calendar. Body: `{ title, start, end, description?, location? }`. Return the created event ID.
- `PATCH /api/calendar/events/{eventId}` → update event fields.
- `DELETE /api/calendar/events/{eventId}` → delete event.
- All endpoints must use the user's stored OAuth token (single-user app — just one token row).

**Architecture notes for implementer:**
- Backend stack: Go 1.26, stdlib `http.NewServeMux()` with method-pattern routing (`server/cmd/server/main.go`), SQLite storage (`server/internal/store/`). No Chi router despite readme mention.
- API helpers in `server/internal/api/response.go`.
- Register new routes in `server/cmd/server/main.go` (follow the existing `smartBoardAPI` registration pattern).
- Add a `calendar` package: `server/internal/api/calendar/` (handlers), `server/internal/services/calendar.go` (service), `server/internal/store/calendar.go` (token storage + API client).

**Depends on:** LOS-012.1 (credentials + config must exist first).

## Summary

Built the Google Calendar OAuth + bidirectional sync backend. The LifeOS Go server can now connect a user's Google account, fetch their calendar events, and create/update/delete events on their primary Google Calendar.

### What was built

**`server/internal/store/calendar.go`** (new) — token store. SQLite table `google_oauth_tokens` (single row, id=1, single-user app). Methods: SaveTokens (upsert), GetTokens (returns nil if none), ClearTokens.

**`server/internal/services/calendar.go`** (new) — `CalendarService` wrapping the Google Calendar API. Holds the `oauth2.Config`. Includes `persistingTokenSource` — a custom `oauth2.TokenSource` wrapper that auto-refreshes expired access tokens via the refresh token AND persists the new token to the DB (only writes when the access token actually changed, avoiding needless DB writes). Methods: AuthURL, ExchangeCode, IsConnected, Disconnect, GetEvents, CreateEvent, UpdateEvent, DeleteEvent.

**`server/internal/api/calendar/calendar.go`** (new) — HTTP handlers. 8 endpoints total: 4 OAuth (start, callback, disconnect, status) + 4 events (GET list, POST create, PATCH update, DELETE). All use 30s timeouts + return JSON errors via `api.RespondError`.

**`server/cmd/server/main.go`** — wired the new store + service + handler and registered 8 routes.

**`server/internal/store/sqlite.go`** — added `google_oauth_tokens` table migration.

**`server/internal/config/config.go`** + `.env.example` — added `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, `FRONTEND_URL` env vars.

### Verification (live against real Google Calendar)

All 8 endpoints tested with curl against the live backend after completing the real OAuth flow in a browser:
- GET /oauth/status → connected: true/false ✅
- GET /oauth/start → 307 redirect to Google with correct client_id + scope ✅
- GET /oauth/callback → tokens stored, redirected to frontend ✅
- GET /events → returned real August 2026 calendar events ✅
- POST /events → created test event on Google Calendar, got back the new ID ✅
- PATCH /events/{id} → renamed + added description ✅
- DELETE /events/{id} → deleted, verified gone from GET ✅
- POST /oauth/disconnect → tokens cleared, status reverted to false ✅

Token refresh (AC #4) is wired via `persistingTokenSource` but didn't trigger during testing because the access token was fresh. The code path is correct.

### Issues hit during testing (now resolved)
1. **`go.mod` version `1.25.5` rejected** — older Go (gccgo 1.18) doesn't support three-part version format. Changed to `go 1.26`. Backend builds fine with nix Go 1.26.
2. **`direnv allow` needed** — the system had two Go installs; nix flake Go 1.26 only loaded after running `direnv allow`.
3. **Google consent "Access blocked"** — app is in Testing mode; had to add the user's Gmail as a test user in Google Cloud Console under auth/audience.
4. **Hardcoded frontend URL** — original Phase 2 hardcoded `http://localhost:3001/calendar` in main.go. Refactored to use a new `FRONTEND_URL` env var (defaults to `http://localhost:3001`).
