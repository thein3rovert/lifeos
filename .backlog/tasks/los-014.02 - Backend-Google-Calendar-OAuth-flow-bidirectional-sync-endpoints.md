## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement the Go backend that handles Google OAuth and the bidirectional Calendar sync.

Part 1 — **OAuth flow:**
- `GET /api/calendar/oauth/start` → redirects to Google consent URL with `calendar.events` scope
- `GET /api/calendar/oauth/callback` → exchanges code for tokens, persists them, redirects to frontend
- Token storage: new `google_oauth_tokens` table (or a JSON column on a settings table). Store access + refresh tokens + expiry.
- Token refresh: a helper that checks expiry and refreshes via the refresh token before each API call.

Part 2 — **Calendar API endpoints:**
- `GET /api/calendar/events?start=<RFC3339>&end=<RFC3339>` → fetch events from the user's primary Google Calendar. Return a normalized JSON shape `{ id, title, start, end, description?, location? }`.
- `POST /api/calendar/events` → create event in Google Calendar. Body: `{ title, start, end, description?, location? }`. Return the created event ID.
- `PATCH /api/calendar/events/{eventId}` → update event fields.
- `DELETE /api/calendar/events/{eventId}` → delete event.
- All endpoints must use the user's stored OAuth token (single-user app — just one token row).

**Architecture notes for implementer:**
- Backend stack: Go 1.26, stdlib `http.NewServeMux()` with method-pattern routing (`server/cmd/server/main.go`), SQLite storage (`server/internal/store/`). No Chi router despite readme mention.
- API helpers in `server/internal/api/response.go`.
- Register new routes in `server/cmd/server/main.go` (follow the existing `smartBoardAPI` registration pattern).
- Add a `calendar` package: `server/internal/api/calendar/` (handlers), `server/internal/services/calendar.go` (service), `server/internal/store/calendar.go` (token storage + API client).

**Depends on:** LOS-012.1 (credentials + config must exist first).

## LOS-014.02 — Backend: Google Calendar OAuth + bidirectional sync

### Patterns to follow (from research)
- **Routing:** Go 1.22+ `http.NewServeMux()` method-pattern (`mux.HandleFunc("GET /api/...", handler)`), `r.PathValue("id")`. Register in `server/cmd/server/main.go`.
- **Store:** interface + SQL impl in `server/internal/store/`. Migrations go in `sqlite.go` `migrate()` as `CREATE TABLE IF NOT EXISTS` queries.
- **Service:** thin pass-through in `server/internal/services/`.
- **Handler:** `server/internal/api/<feature>/` package, `api.RespondJSON` / `api.RespondError` / `api.DecodeJSON` from `server/internal/api/response.go`.
- **Config:** already added `GoogleClientID`, `GoogleClientSecret`, `GoogleRedirectURI` (LOS-014.01).

### Phase breakdown

**Phase 1 — DB migration + token store**
- Add `google_oauth_tokens` table to `sqlite.go` migrate(): `id`, `access_token`, `refresh_token`, `expiry`, `token_type`, `updated_at` (single-user → single row)
- New file `server/internal/store/calendar.go`: `CalendarStore` interface + `SQLCalendarStore` with `SaveTokens`, `GetTokens`, `ClearTokens`
- Wire store in `main.go`

**Phase 2 — OAuth flow handlers**
- New file `server/internal/api/calendar/calendar.go`: `CalendarHandler` struct holding config + store
- `GET /api/calendar/oauth/start` — builds OAuth config, redirects to Google consent URL with `calendar.events` scope
- `GET /api/calendar/oauth/callback` — exchanges code for tokens, persists via store, redirects to frontend `http://localhost:3001/calendar`
- Register routes in `main.go`

**Phase 3 — Token refresh + Google Calendar client**
- Token refresh helper: checks expiry, refreshes via `oauth2.TokenSource`, persists new tokens
- `CalendarService` wrapping `calendar/v3.Service`: `GetEvents`, `CreateEvent`, `UpdateEvent`, `DeleteEvent`
- New file `server/internal/services/calendar.go`

**Phase 4 — Calendar API endpoints**
- `GET /api/calendar/events?start=&end=` — fetch + normalize events
- `POST /api/calendar/events` — create event
- `PATCH /api/calendar/events/{eventId}` — update event
- `DELETE /api/calendar/events/{eventId}` — delete event
- `POST /api/calendar/oauth/disconnect` — clear tokens
- Register all routes in `main.go`

**Phase 5 — Verification**
- `go build ./server/...`
- `go vet ./server/...`
- curl smoke test: OAuth start redirect, token storage
